## P35: a real pretrained retrieval protocol, with a full-corpus requirement

The [pinned retrieval command](https://github.com/DeepGraphLearning/ProtST/blob/db53a76ed2430eb66dd9c8134ace99fd60980fb3/script/run_t2p_retrieval.py) constructs the complete configured GeneOntology dataset and never calls its split method. Its ranking universe includes training, validation and the configured 95%-filtered test data. Replacing this universe with the already acquired test archive would change results.

The outer archive is 1,691,808,865 bytes. The missing train and validation members total 1,506,462,743 bytes; test.zip was acquired during the earlier DeepFRI audit. Complete archive MD5 and historical parsed case identity have not been established. Historical loader counts are not reliable executable manifests: the earlier current-RDKit residue projection retained 3,129 test cases rather than the printed 2,991, and did not execute every TorchDrug graph operation.

The [source config](https://github.com/DeepGraphLearning/ProtST/blob/db53a76ed2430eb66dd9c8134ace99fd60980fb3/config/t2p_retrieval/go_mf.yaml) uses ESM-1b and PubMedBERT joint projections with normalized 512-dimensional representations. Retrieval consumes PDB-modeled residues, has no annotation-specific 550-residue crop, and retains the native ESM 1,022-residue model limit. Full released FASTA is a different input condition. The 8,531,223,409-byte pretraining checkpoint contains learned projection parameters; no new downstream head is needed. Only checkpoint metadata was inspected.

The source returns global top-k PDB IDs, default20, per fixed query. It does not implement aggregate Recall@K or accuracy. The [paper](https://proceedings.mlr.press/v202/xu23t/xu23t.pdf) provides selected retrieval/structural evidence; that does not define a new full-test headline metric. The exact498-byte query file is now Git-blob/SHA-verified and input-only reviewed: five ordinary ATP/heme/GTP/pyridoxal-phosphate/NAD binding retrieval queries. This does not authorize inference. Native work is one encoding per retained protein, five text encodings and5×N dot products. A prospectively frozen Qwen scalar-likelihood ranking is also a valid adaptation:5×N pair scores over the complete native universe, conditionally167,700 if the unverified historical33,540 count held. Complete modeled sequences must remain retained and any native1022-residue versus full-sequence condition disclosed. Current N and throughput are unknown; no runtime promise or relevance metric is invented.

## P36: an available artifact does not resolve the metric discrepancy

The full JSON `tasks_plus/task234_protein_design_molinst_pro_test.json` at [BioT5_finetune_dataset revision9f70da9](https://huggingface.co/datasets/QizhiPei/BioT5_finetune_dataset/tree/9f70da9e8f0df32e7e62846f7ad78a829b00c0fd/tasks_plus) is now acquired and verified against LFS SHA-256 `d1239080c09194a71b71374cc4a976ae48184981c14caafce55ec82b2281d880`. A deterministic parser inspected only schema, IDs and lengths:5,876 unique IDs, inputs40–1,618characters and instructions70–112characters. Input text and sequence targets were never exposed to the assistant. All cases remain unreviewed and undispatched. Publisher instance-license metadata says `Unknown`; repository MIT is not evidence of resolved instance-level terms. The earlier component's metadata-only finding is retained unchanged; the new acquisition receipt and ID inventory record this subsequent step.

The [design invocation](https://github.com/QizhiPei/BioT5/blob/cf65ae6dff63fdea8883dd17d46728a61bba386c/biot5_plus/evaluation_mol_instruction_protein.sh) routes to `molinst_pro_understand`. Its metric receives decoded `(target,input)` pairs, allowing the input as an alternate reference under the cached HF ROUGE implementation. Two synthetic examples returned paired ROUGE-L `[1.0,1.0]` versus target-only `[0.0,0.5]`. Historical `evaluate.load("rouge")` resolution is unpinned, and the absent evaluate/datasets runtime was not installed. This verifies wiring and the cached component, not exact historical equivalence.

Native input and generation caps are512 and256 tokenizer tokens, respectively. The prediction tokenizer recreates protein-token IDs as nonspecial, so `skip_special_tokens` does not imply loss of those tokens. No arbitrary residue cleanup is justified. The [paper, sections4.2.4/G.3/H.2](https://arxiv.org/html/2402.17810v2) describes selected design examples and normalized Smith–Waterman similarity; scoring parameters, normalization and complete-case failure policy are unrecovered. Neither a convenient Smith–Waterman default nor a silent ROUGE correction may stand in for that contract. Detailed source and synthetic evidence: [P36 component](../sources/remaining_design_source_audit_2026-10-15/biot5_design_contract_review/component_summary.json).

A concrete route remains available: independently review only source instructions/inputs, keep targets scorer-side, freeze a Qwen sequence serialization and exact cached paired-reference ROUGE runtime, and evaluate every declared eligible source-order slot under the existing4096-token recipe. The maximum unfiltered scope is5,876 n=1 generations; actual permitted count and token/runtime sizing are not yet established. This would be a qualified released-code ROUGE baseline, not an exact trained BioT5+ condition or paper Smith–Waterman reproduction. Missing paper scoring parameters do not rule out that route.

## P39: preserve both conditioning channels and the complete evidence pipeline

The [NatureLM case study, section4.5](https://arxiv.org/html/2502.07527v3) uses function text and heme SMILES as distinct conditions, then self-generated descriptions, a keyword screen and predicted complexes. The exact cohort, sampling rules, keyword list, predictor settings and acceptance criteria were not recovered from the [pinned publisher tree](https://github.com/microsoft/SFM/tree/bcb1351bc6490d4a98cae74e7eead30a028fae00/NatureLM). Selected predicted complexes do not supply independent experimental binding labels or a full-cohort accuracy denominator. A future local case study must freeze its budget, complete selection and external evaluator before any generation and disclose that it is a new qualified protocol. No numerical workload or binding score is fabricated.

Ordered IDs and all source anomalies remain preserved in the [component audit](../sources/remaining_design_source_audit_2026-10-15/rabd_upstream_review/component_summary.json); no raw complex was acquired.

Native AAR uses positional matches divided by full native CDR length: absent suffix positions reduce recovery, extra predicted suffix is ignored. The upstream evaluator averages per-complex values and also consumes coordinates for structural metrics. Its checked-in wrapper requests one sample, overriding parser defaults of10,000 samples/top100. That current invocation does not establish any paper's historical sample budget. Five synthetic edge cases verify the primitive and macro-versus-residue aggregation distinction.

MEAN retains heavy/light framework and structure-selected antigen-interface residues with backbone coordinates. NatureLM reports a separate sequence-only antigen/framework condition. Proteo-R1 uses a structural IMGT H3 condition and evaluates geometry/interface metrics as well. Upstream60 does not prove either target-specific processed set or its final retained count. Exact masks, context construction, allowed case scope, sample policy and scorer must be recovered before preparation; native target residues remain scorer-only. No unreviewed antigen request is authorized.

## P41: native specialist execution is legitimate, but demos are not the holdout

The [213-entry pinned release](https://github.com/smiles724/Proteo-R1/tree/ffaa787bce5f30e4cb41e2de5d0b0daab0059243) supplies five demonstrations, native helpers and checkpoint links, but no verified paper holdout manifest. The [paper](https://arxiv.org/html/2605.02937v1) specifies a date-and-H3-cluster split, fixed framework context, multi-CDR structural outputs and external proxy metrics. Exact retained IDs, candidate count and complete benchmark evaluator remain unrecovered. Generic structural losses are present; they do not resolve full benchmark aggregation.

The runtime couples a Qwen3-4B/Protenix understanding expert to a Boltz1 coordinate generator through CDR hidden states. The documented quality condition requires canonical masks, processed MSA and frozen scaffold assets. Current masking helpers use Chothia/abnumber; the paper's RAbD IMGT H3 condition must remain distinct. Neither full framework/antigen context nor 3D input may be discarded to fit a text adapter.

HF metadata identifies 8,075,140,776 bytes of understanding weight files and1,781,952,264 bytes of generator weight files; this is an inventory, not a measured simultaneous-loading requirement. The README advertises additional~7GB external weights and~330MB caches. Python3.12, pinned Transformers4.57.1, Protenix submodule and structural dependencies require a separate reviewed environment. No weights, demo structures, environment installation or forward was performed. One H200 may be sufficient, but no measured memory/time supports a claim yet. Seven active chat replicas do not resolve missing holdout identity or evaluator assets.
