# Method and limits

## Fixed selection and reviewer visibility

The original admitted cohort contains 1,736 questions. This reassessment selects exactly the 1,328-question union for which either old review was format-valid and labeled lookup_or_memorization_dependent or cannot_determine. Selection uses only saved prior results, in original packet order. The other 408 admitted questions are listed in NOT_REASSESSED.md and not reassessed; 61 earlier source-question exclusions remain outside the admitted cohort. The old report remains unchanged.

Both models receive the same selected questions, revised logical system message and exact unchanged reviewer user message. The user message includes complete original system and user instructions, sequence, ordered choices, author key and reviewer-only source evidence. Reviewers do not receive prior verdicts/reasons, selection metadata, the other reviewer’s output, an original evaluated-model answer, or its correctness outcome. Evidence, original question inputs, author keys and output schema are unchanged. There is no developer message in the logical requests. Exact old/new system instructions and user template are in REVIEWER_PROMPTS.md; all exact unchanged reviewer user messages are in inputs/.

## Clarified transfer criterion

The revised prompt permits concrete transferable knowledge of related proteins, families, homologs, conserved features, structures, mechanisms, analogies and learned biological patterns. A credible probabilistic inference can count if it meaningfully distinguishes the actual offered choices. It need not independently prove every detail or discriminate unoffered alternatives. Exact-target record recall remains lookup-dependent. Merely lacking an argument is not proof that memorization is necessary. Reviewer-only target annotations are not original inputs. Numerical precision alone does not determine either label. Full instructions, not this summary, define the condition.

Key support remains a separate assessment of the supplied author answer against reviewer-only evidence. Source-supported does not imply transfer-supported. Original benchmark solving, original model responses, training effects and reasoning faithfulness are not evaluated.

## Execution and output usability

Usable output means a format-valid review, separate from its scientific classification. A usable review can label the question reasoning-supported, lookup-dependent or uncertain; it does not certify biological correctness. An output error counts an unusable model response, not a defective question, wrong key or unsupported biological claim. Canonical saved statuses such as valid_review and invalid_review are retained verbatim in machine-readable records.

Both models have one generation attempt per selected case; no benchmark pilot, output-error retry or consensus pass is added. Failed, incomplete, malformed and empty-final outputs remain terminal and visible. Each case page and reviews.jsonl preserve actual status, full saved parsed visible value and exact saved final string. Parsed JSON nulls and other output errors, wrong option IDs, nonexistent citations and missing fields are never repaired. No internal provider reasoning, encrypted payload, headers, response IDs, credentials or private runtime paths are published or substituted for a final answer. An empty visible final is distinct from a missing question or attempt.

CONDITIONS.json records exact allowlisted new dispatch settings and pinned runtime versions. BEFORE_METHOD.md reproduces the old published conditions for comparison. Model identities, pinned Qwen revision, sampling values, output/input ceilings and maximum concurrency are retained; the logical system prompt changes and the selected cohort is smaller. The combined output ceiling is 16,384 tokens and the input ceiling 49,152 within 65,536 context; there is no separate thinking/final limit. Native termination is required for a usable review output in addition to strict schema, supplied evidence/option IDs and input-gate checks. Luna provider revision, precision, hardware and internal chat formatting are unavailable. Qwen uses the pinned native chat template with enable_thinking=true and reasoning_effort=medium; boundary whitespace is trimmed and assistant <think> generation prefix is added, without an additional natural-language instruction. Logical prompts are identical across reviewers; physical API/template serialization is different. Luna’s input gate combines a conservative canonical UTF-8 byte bound plus 2,048 for unflagged cases with authoritative input-token counts for the 32 flagged cases. This is not an exact tokenizer count for every Luna input. There is no prompt truncation.

Actual saved generation input, output, cached-input, cache-write and reasoning-token usage is aggregated separately from cost in summary.json; per-field observation counts distinguish missing usage from reported zero. Luna responses return prompt_cache_retention=24h although the request omitted that option. This is observed provider metadata, not a configured request setting. A matching documented cache-write rate or invoice is unavailable here, so exact cache-write and total dollar charges remain unknown. The inherited record estimator contains illustrative 30m/12h scenarios and a partial sum for fully priced responses; those values are not a total cost or defensible billing bound for returned 24h retention and are not presented as such. Input-count calls and GPU allocation charges are separate from generation usage. Qwen has no per-request local API charge; its GPU allocation charge is unknown.

## Denominators

Each model/round label distribution uses only that model/round’s usable outputs; counts and output-error/missing records are shown separately. Each model’s old → new label transition table uses the fixed same-model case intersection with usable outputs in both rounds. Cases with old output errors are separately enumerated, even if their new review output is usable. New intermodel agreement uses the new pairs with usable outputs from both models. Round-specific old/new agreement is descriptive and shows its own denominator.

The BEFORE/AFTER AGREEMENT COMPARISON uses only the identical four-way format-valid intersection: usable old Luna, old Qwen, new Luna and new Qwen outputs for the same cases. Both rounds use that same denominator and exact case list, avoiding a change caused merely by different output-usability cohorts. Labels from output errors are never salvaged into distributions or converted into cannot_determine.

## Evidence, old notes and interpretation

All source evidence is reused unchanged. No new biological source retrieval or scientific audit is performed. Historical UniSave sequence matches, current-record mismatches, source identity, annotation/computational/experimental qualifiers and unknown exact author snapshot remain explicit. Accession identity was recovered from dataset image-path metadata unavailable to the original evaluated model. Gene Ontology evidence postdates the benchmark; supplied graph paths use only is_a and part_of. Absence of a supplied annotation is not proof of falsehood. Primary papers were not comprehensively independently assessed.

Existing project source checks are copied exactly from the old public report and apply only to the old Luna claims. They are not new validation of either revised review or old Qwen. Contradicted keys remain review flags, not confirmed key errors. There is no expert adjudication, new gold answer, forced consensus, rescoring, training or faithfulness review. Agreement is not scientific truth, and a shared source can induce shared errors. The selected cohort is conditioned on prior lookup/uncertain judgments and cannot estimate the distribution over all 1,736 questions. One attempt per prompt cannot isolate a causal prompt effect from sampling variation or service differences.

## Export and freezing

Public files are built from explicit field allowlists. Full visible reviews and original input strings remain unchanged; Markdown presentation escapes characters only outside exact text blocks. The prior public tree is verified against its frozen manifest and never written. A candidate is prepared only after both exact-scope terminal client audits pass. An independent verifier must accept its exact inventory before publication manifest and EXPORT_READY are created. Public provenance includes hashes and allowlisted audit counts, not raw private audits. Publication is handled separately.
