# Description-guided protein generation: prepared subset

**59 cases are prepared for Qwen3.8-27B. This is a partial evaluation, not completion of the 5,876-case source test.** No model inference was performed by this preparation agent.

The first 64 source-order instruction/input pairs were individually reviewed before any Qwen outputs. Each approved ID has a benign-purpose reason in `input_review.json`. Five prefix cases remain held for viral/toxin goals or unresolved neuroactive effects; the other 5,812 source cases remain unreviewed and held. Keyword screening across the source only records review markers; absence of a marker never approves a case. Targets were not used for eligibility or placed in requests.

The exact [public test artifact](https://huggingface.co/datasets/QizhiPei/BioT5_finetune_dataset/blob/9f70da9e8f0df32e7e62846f7ad78a829b00c0fd/tasks_plus/task234_protein_design_molinst_pro_test.json) was reacquired because the prior report's raw artifact was absent from this checkout and its initial backup manifest. Its 14,344,274 bytes match SHA-256 `d1239080c09194a71b71374cc4a976ae48184981c14caafce55ec82b2281d880`. All 5,876 IDs are unique. Publisher instance-license metadata remains `Unknown`; repository MIT does not resolve those instance-level terms.

The frozen input uses each native instruction and description in the official Alpaca template. A fixed system instruction requests the source's `<bop>` / per-residue `<p>` / `<eop>` serialization. Qwen receives full descriptions, no reference sequence, and no tools. Original BF16 Qwen3.8-27B uses the existing fixed 4,096-output-token, seed42, medium-thinking, n=1 recipe with one concurrent request.

The [released design command](https://github.com/QizhiPei/BioT5/blob/cf65ae6dff63fdea8883dd17d46728a61bba386c/biot5_plus/evaluation_mol_instruction_protein.sh) selects `molinst_pro_understand`. [Prediction code](https://github.com/QizhiPei/BioT5/blob/cf65ae6dff63fdea8883dd17d46728a61bba386c/biot5_plus/utils/train_utils.py#L148) supplies decoded target/input pairs. Its [metric wrapper](https://github.com/QizhiPei/BioT5/blob/cf65ae6dff63fdea8883dd17d46728a61bba386c/biot5_plus/metrics/pro_understand_metrics/pro_understand_metrics.py) passes those pairs to ROUGE, including the input as an alternate reference, and returns ROUGE-L. This behavior is preserved rather than silently replaced with target-only scoring.

The prospective scorer executes the two pinned source `_compute` methods verbatim, replacing only unpinned network resolution with [HF ROUGE revision 1bc20e7](https://huggingface.co/spaces/evaluate-metric/rouge/blob/1bc20e7e9df922e5dfb597c31a4ea8467a89caff/rouge.py). Its dependencies and bootstrap seed42 are fixed. Raw final content is scored without trimming, sequence repair or favorable sample selection. Missing/failed slots receive empty predictions and remain in the 59-slot denominator. Malformed and length-stopped outputs remain raw and are separately counted. Outputs and missing slots are hash-locked before opening scorer references.

**This lexical metric does not establish biological design success.** Synthetic checks show an input echo scores paired ROUGE-L 1.0 while the same prediction scores 0.0 against its target alone. Two toy sequences with no shared residue still score 0.667 from their common serialization tokens. These are synthetic checks, not benchmark results.

This full-text Qwen adaptation differs from trained BioT5+ tokenization, native 512-input/256-target token caps, native decoder cleanup and greedy generation. The historical unpinned `evaluate.load("rouge")` dependency is unknown. The [paper](https://arxiv.org/html/2402.17810v2#S4.SS2.SSS4) instead presents selected examples with normalized Smith–Waterman scores and notes manual terminal-repeat truncation. Exact alignment/normalization and cohort/failure contracts remain unrecovered, so no paper score or replacement alignment metric is claimed.

All six synthetic protocol tests passed: reference-pair wiring, serialization artifacts, target exclusion, disabled-dispatch gate, all-slot denominator/raw invalid output retention, and output-lock mutation rejection. Fifteen acquired source-file hashes and the exact ordered input-review contract also passed verification.
